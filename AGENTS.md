# Agent and contributor instructions

## Project and scope

SPlayer-Z is an offline-first Linux music player built with Electron, Vue 3, TypeScript, and Rust NAPI-RS modules. Work on **dev** unless explicitly directed otherwise. Preserve the root **README.md** unless the user explicitly authorizes changing it. Do not write chat handoffs or task-specific commentary into public documentation.

Use local files and authorized self-hosted media servers as the product boundary. Public KG/QM playback and logins, cloud navigation, recommendation features, plugins, external HTTP/WebSocket/MCP services, AI integration, music recognition, public lyric lookup, and the separate local TTML library are not supported features. TTML file support, local liked songs/playlists, and authorized media-server caching/downloads remain. Legacy files and types are not proof that a removed feature should be enabled.

Support only x86_64 Linux and ARM64 Linux. Do not add Windows, macOS, 32-bit, or universal build targets, OS fallbacks, or platform-exclusive integrations. Keep both Linux CI architectures covered.

## Commands and environment

Use the Node/pnpm versions in `package.json`. Use bash syntax for Linux shell examples and do not assume fixed filesystem paths.

```bash
pnpm install
pnpm dev                 # Debug native build and Electron development
pnpm build               # Native build, type checks, Electron bundles
pnpm build:linux         # Linux package for the host architecture
pnpm build:native --dev  # Debug native modules
pnpm typecheck
pnpm lint
pnpm test
pnpm docs:build
cargo check --all-targets --locked
cargo test --locked
```

Format each changed file with Prettier before committing; do not run a whole-repository formatter that changes unrelated files. `SKIP_NATIVE_BUILD=true` skips compilation but does not create missing native outputs.

On Nix, `nix build .` produces `./result/bin/splayer-z`; `nix develop` provides the development toolchain. The flake sets `FFMPEG_MODE=system` and declares FFmpeg, PipeWire, PulseAudio, ALSA, OpenSSL, D-Bus and pkg-config. Host-installed tools do not satisfy sandboxed derivation inputs. Do not claim zero system dependencies or describe the audio engine as rodio-based.

## Architecture and ownership

- Main process: `electron/main/`; native loading, configuration, databases, authenticated server operations and IPC registration.
- Preload: `electron/preload/`; typed `window.api` bridge and per-handler event subscriptions.
- Renderer: `src/`; Vue interface, Pinia stores, playback coordination and presentation.
- Shared contracts: `shared/types/` and `shared/defaults/`.
- Settings: `src/settings/schema.ts`, category implementations in `src/settings/categories/`, schema types in `src/types/settings-schema.ts`.
- IPC registration: `electron/main/ipc/index.ts` is authoritative. Do not implement unregistered legacy API calls to silence obsolete callers.

### Native build

`scripts/build-native.ts` builds only `audio-engine`, `media-ctrl`, and `opencc`. Native manifests, Nix systems, and build validation restrict supported targets to x86_64 and aarch64 Linux.

`audio-engine` uses `ffmpeg_audio` for decoding, CPAL with Linux PipeWire/PulseAudio/ALSA output. DSP handles equalization, normalization, rate/pitch processing, limiting and FFT. Respect load generations and cancellation when changing decoder ownership. Types are generated by NAPI-RS, never copied by hand.

`media-ctrl` provides Linux MPRIS system media controls and Discord integration. Retired Desktop Lyric, Dynamic Island, and Windows taskbar integrations are removed.

### Playback and queue

`src/core/player` coordinates renderer playback through IPC and the native engine. `src/stores/status.ts` holds low-frequency reactive state; `src/services/playback.ts` interpolates time without frame-rate Vue mutations. `src/stores/media.ts` holds a lightweight current track and on-demand detail.

`useQueuePanel` shares popover and Now Playing queue behavior. `useDragSort` handles mouse/touch ordering, insertion geometry, auto-scroll, cancellation and release-click suppression. Reorder through core player operations, preserve the playing entry and time, persist the order, and key duplicate tracks by queue-entry identity. Keep keyboard arrow reordering and focused-handle restoration working.

### Library, Home and search

Use the shared `SongList` layout for song tables, including Genre where applicable and matching header/row widths. Do not duplicate page-specific grids. Local metadata artist exceptions live in `electron/main/utils/metadata.ts`; preserve **Royal & the Serpent** as one artist without disabling normal credit splitting.

Home contains the random library selection and Stats below it. `/stats` redirects to Home. Do not restore a separate Stats page or recommendation sections.

Home's top search is global and categorized across local indexes and the active server's synchronized library. Other library pages use route-bound contextual filters through `usePageSearch`; do not add a second Library search bar. Clear must clear the query and visible results. Search playback behavior is a separate queueing preference, not search scope.

### Lyrics and player rendering

AMLL is the only Now Playing lyric engine. Source resolution lives under `src/services/lyric/`; parsing and safe inline emphasis live under `src/utils/lyric/`. `external` covers sidecars and configured-server lyric responses, not public lookup.

Normalize compact line-timed LRC without splitting word timestamps into lines. Preserve word timings and text offsets when parsing `**bold**`, `*italic*` and nested emphasis. Bold is uppercase in presentation; italic endings need clearance without changing source text. Never execute arbitrary lyric markup.

Initialize fluid rendering during player entry; do not wait for the entry transition to complete or first show a blurred-cover preview. Guard asynchronous cover readiness against stale tracks, cancel scheduled frames, and dispose renderers on close.

### Media servers

`electron/main/services/streaming/` owns Subsonic-compatible, Jellyfin and Emby adapters, encrypted configuration, connection sessions, authenticated cover proxying, atomic SQLite snapshots, favorites and playback reporting. The renderer consumes secret-free views and synchronized indexes, not direct authenticated server requests.

Trust server artist fields without client-side splitting. Preserve server ID, original media identity, and media revision through navigation, queueing, caches and downloads. Renaming a server must not change media identity. A failed sync keeps the last complete snapshot; favorites must not be overwritten by late pages. Preloading and downloading must not report playback.

Credentials prefer Electron safeStorage; streaming and Last.fm have a logged Base64 fallback when unavailable. Base64 is not encryption. Never expose passwords or access tokens in renderer-visible URLs or logs. `streaming-cover://` is a main-process authenticated proxy.

### Storage and localization

`electron/main/utils/paths.ts` defines `{userData}/app-data/`, containing `config/`, `database/library.db`, `cache/`, and `logs/`. Main configuration uses atomic writes and migrations. Renderer localforage stores include `splayer-z/library` and `splayer-z/queue`; local playlists use SQLite, with the old renderer playlist store used only for migration.

Use 300px cover thumbnails for lists, sampling and blurred backgrounds. Full-resolution artwork belongs only on visibly large covers or exports. Respect custom cache paths and Electron's Linux user-data paths.

English is the default for renderer, main-process and reset paths; saved preferences take precedence. Setup starts with the language picker. Renderer translations live in `src/i18n/locales/`; main tray translations live in `electron/main/utils/i18n.ts`. Keep localized strings in their intended language.

## Validation and documentation

Run relevant tests, type checks, lint and builds. Real audio tests and `.node` integration tests require native outputs and suitable runtime services; `scripts/test-pipewire.sh` preserves logs and discovers Nix configuration paths. Do not weaken assertions or claim a check passed if the environment prevented running it.

For UI changes, validate pointer, keyboard, narrow/wide layouts, cancellation, and persistence. Browser previews do not replace real Electron or main-process memory checks. Document actual validation gaps in the handoff, not in README.

Canonical documentation is English under `docs/`; `docs/en/` uses includes to preserve old English URLs; its homepage mirrors root frontmatter. Update canonical pages and navigation, remove obsolete feature instructions, and build the documentation. Keep license notices and attribution. Do not silently change legal liability or jurisdiction provisions during a translation task.

See `docs/architecture.md`, `docs/native.md`, `docs/types.md`, and `docs/contributing.md` for detailed references.

## Conventions

### Project Language

English is required for all future commit messages (subjects and any bodies), pull request
titles and descriptions, review discussions, documentation, contributor instructions, and
new or updated code comments. Existing non-English content may be translated incrementally;
do not rewrite old commit history solely for translation. Application localization strings
may remain in their target languages. See `docs/contributing.md` for the contribution guide.

### Comments — English, with JSDoc

Write all new or updated comments in English. Every newly added or modified method must have a concise, meaningful
JSDoc description of its purpose and parameters, using `@param name - description` and
`@returns` when meaningful. This applies to internal helpers, class methods, adapter methods,
and exported APIs. Anonymous callbacks do not need redundant explanations of obvious logic

Keep English comments and JSDoc concise and natural. Preserve the target language of localized UI copy.

```ts
/**
 * <English method description>
 * @param trackId - <English parameter description>
 * @returns <English return description>
 */
```

Forbidden: `// ───` separator lines (including ones with section titles), prose-style multi-paragraph comments, restating-the-obvious comments, numbered enumerations (`1. 2. 3.`) inside comments. Write comments only when the **why** is non-obvious.

### Code Organization

Split logic into files rather than separator comments. Don't extract a helper for one-place callers (3+ uses justify it). No "just in case" defensive code or fallbacks for impossible scenarios. No configurable knobs (timeouts / retries / buffer sizes) unless required — write constants. Don't break errors into per-case enums; `anyhow` or plain `Error` is usually enough.

### Memory Discipline

Memory is a hard requirement. The main process logs memory usage through `app.getAppMetrics()`
60 seconds after launch and then every 10 minutes. When a change touches rendering, caching, or
IPC, verify before and after with these samples.

- **Images by display size** — anything blurred, sampled, or rendered small uses the 300px `cover` thumbnail (player blur background, color extraction, lists). `coverOriginal` only for the visible large cover and poster export. Large `<img>`: add `decoding="async"`; preload with `img.decode()` before fading in.
- **Compositing layers are budgeted** — never put `will-change` in CSS on unbounded element collections; promote dynamically and only near the viewport (lyric engine `lineWillChange` pattern). New full-screen `filter: blur` / `backdrop-filter` layers need justification.
- **Hidden = silent** — high-frequency pushes (`position` / `fftData` / `position-sync`) must not reach hidden windows: `broadcast(channel, data, true)` or an `isVisible()` gate; consumers recover from the next push (≤200ms), no resync needed. Low-frequency state events (`stateChanged` / `ended` / track-change) always go through. RAF loops and canvases must stop when their surface is hidden (engine `freeze()` / `visibilitychange` pattern).
- **In-memory caches must be bounded** — every module-level Map/array cache needs an eviction rule (subsonic `viewAuthCache` evicts per-server). Never retain `TrackDetail`-sized data beyond the current track.

### Units

Frontend time is **milliseconds** everywhere. Rust engine uses seconds internally; `toMs()` in `electron/main/ipc/player.ts` converts.

### Types & Persistence

Never hand-write native module types — import from `@splayer/*`. Use `shallowRef` for `Track` arrays/collections (avoid deep proxy). Vue proxied objects can't be cloned by IDB (`DataCloneError`); use `toRaw` before persisting.

### Auto-imports

In Vue components, `vue / pinia / vue-router / @vueuse/core / vue-i18n` are auto-imported, and UI components in `src/components/` are auto-registered.
Icon components used only in Vue templates are auto-imported. Do not manually import them in
`<script setup>`; import an icon explicitly only when it is referenced by script code.

### Logging (Main Process)

Use scoped loggers from `@main/utils/logger` (`coreLog / playerLog / mediaLog / trayLog / nativeLog`, etc.). Don't import `electron-log` directly.

### IPC Listeners

The preload `subscribe` helper adds one handler and returns an unsubscribe function that removes only that handler. Never add `removeAllListeners` to individual shared channels. Finite-lifetime consumers must call unsubscribe in `onBeforeUnmount` or `onScopeDispose`; application-level singleton subscriptions intentionally live for the process lifetime.

### Prettier

Double quotes, semicolons, 100-char width, trailing commas.

Before committing, run Prettier on every file included in the commit and verify the formatted
working tree before creating the commit. Do not leave formatting-only changes from the current task
outside the commit.

### Shared Types

Put cross-process types (`LocaleCode / SystemConfig / StreamingServerType`, etc.) in `shared/types/`.

### Commit Messages

Use Conventional Commits with an English summary: `<type>: <summary>`. Keep the title on one line;
do not add a body or bullets unless explicitly requested. Use the type that matches the change,
such as `feat`, `fix`, `refactor`, `perf`, `docs`, `test`, `build`, `ci`, `style`, or `chore`.
